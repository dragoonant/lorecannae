## 1. The standard project skeleton and file conventions

There are two families. **Card games use the plain-JS family**; everything 3D uses the Vite/TS
family. Lorcana is a card game: use the plain-JS family, with the 3D family's process ideas where
noted.

### 1.1 Plain-JS card-game family (MANAFORGE, MythosForge, ChampionsForge, BreachForge, GRAND LINE, RIVALFORGE)

**Stack.** No build step, no `package.json`, no dependencies. Plain browser JS, every file an
IIFE on one global namespace (`window.MF`, `window.AH`, `window.CF`, `window.RB`, `window.OP`,
`window.RF`). `index.html` declares the script order, with a `<!-- ui -->` marker between engine
and interface. Runs from `file://` and from `node tools/serve.mjs <port>`. All tools are Node
`.mjs`, zero dependencies (MythosForge says Node 24). Sources: MythosForge CLAUDE.md "The hard
rules" 1; ChampionsForge PLAN.md D5 ("Vite/TS was for 3D, not card games", citing
MALLET-42K-LESSONS §6).

**Layout** (MythosForge CLAUDE.md "Layout", MANAFORGE CLAUDE.md "Layout"):

```
index.html            entry point; its script list IS the load order
tests.html            loads the same engine files in the same order (asserted by check-pages)
js/                   ns, engine, ops, bot/ai, then the interface
data/cards.js         GENERATED by tools/build-cards.mjs from scratch/ dumps; never hand-edited
data/decks.js         decks and deck legality
data/defects.js       the gate: listed cards/decks are hidden from the player
tools/*.mjs           serve, test, check-pages, sim, build-cards, audit-cards, gate, gen-art, gen-audio...
tests/NN-area.mjs     one file per area; each test named for the card or the rules term
docs/rules.md         citation index into the official rules (by section or by glossary term)
docs/sources.md       where every rule and card came from, with fetch dates and byte counts
docs/rights.md        what the rights holders publish (MANAFORGE, GRAND LINE); sources.md doubles as it elsewhere
docs/takedown.md      the exact commands that end a deployment
scratch/              gitignored: rules text, card-database dumps, PDFs, sandboxes
art/ audio/           delivery encodes only; masters and archives gitignored
```

**The registers** (MANAFORGE CLAUDE.md "Registers"; OVERNIGHT-BUILD-PLAYBOOK §9; RIVALFORGE
CLAUDE.md "Layout"). Each file has a header saying it is not the others:

| File | Holds |
|---|---|
| `PLAN.md` | **every decision** as a numbered, dated table row (`D1 \| date \| decision \| by: owner/default/handoff`), a "Cut order if time runs short" list, and a **dated Status** rewritten each session (newest first). No other file states a decision; they point at it. |
| `DEVIATIONS.md` | rules the engine does not yet keep, each naming the rule section/term it breaks, retired in the commit that makes it untrue; plus a "Not deviations" list so refusals and deliberate shortcuts are not mistaken for bugs. |
| `TODO.md` | wanted improvements to things that already work; each entry says what exists today, the constraints, and "done when". |
| `data/defects.js` | cards that do not behave as they read; wired into the deck picker so they cannot reach the player. |
| `BALANCE.md` | only for an ORIGINAL design (RIVALFORGE). For a reproduction "the publisher owns balance; there is no BALANCE.md" (MANAFORGE, MythosForge, GRAND LINE regime 2). |
| `NOTICE.md` | non-affiliation, what is and is not included, takedown pointer, "Built by evilgouki". |
| `HANDOFF.md` | (ChampionsForge) where things are by area, how a rule flows, gates, open items in priority order. |

**Engine surface** (identical in every card game): `legalActions(s)` / `apply(s, action)`
(deep-copies, never mutates) / `isTerminal(s)` / `whoActs(s)`, plus `newGame`. Every UI
affordance derives from `legalActions`; every number shown comes from an engine function
(`MF.chars`, `AH.skillValue`, `AH.testOdds`, `CF.stat`, `*.costOf`, `*.whyNot`). One resolution
queue is the whole control flow; a pending head that asks owns the game; `legalActions` throws on
a head that offers nothing. One door per rule (`ask`, `pay`, `dealDamage`, `move`, `draw`...),
with `tools/check-pages.mjs` grepping for the bypasses that have actually happened. Seeded RNG;
every shuffle happens inside `apply`. No silent fallbacks (`if (!NS.x)` and `NS.x || {}` are
grepped and refused). Sources: MANAFORGE CLAUDE.md hard rules 1-12; MythosForge hard rules 1-13;
ChampionsForge hard rules 1-10.

**Cards are data compiled from the printed text** by a grammar (`tools/build-cards.mjs`), every
pattern anchored to the whole sentence. New op = handler + compiler pattern + describer + test.
A card the compiler cannot read in full is `un` and validation refuses it from any registered
deck. `tools/audit-cards.mjs` diffs the describer's prose against the printed text (the
describer "survives only as the auditor"). Source: MANAFORGE hard rule 8; MythosForge hard
rule 7.

**The gates, in one quiet command** (`tools/gate.mjs`, MythosForge and ChampionsForge, new since
Oct 3). MythosForge's runs 11 steps and prints one line each: build-cards, test, check-pages, sim
random (60 games), sim greedy (20), replay `--selftest`, audit, audit `--selftest`, rules-index
`--check` (every cited rule term exists), check-art, art-prompt lint. Source: MythosForge
`tools/gate.mjs`, PLAN.md Status 2026-10-17.

**`tools/serve.mjs`**: a ~20-line static server with `Cache-Control: no-store`, a MIME table, and
a 403 for `scratch/`, `.git` and `tokens*` paths; port from `argv[2]` (BreachForge reads `PORT`
from the env so worktrees each get their own). `.claude/launch.json` has one entry pointing at it.
**Ports already taken**: ChampionsForge 8190, MythosForge 8197 ("8190 belongs to ChampionsForge"),
BreachForge 8777, Dead-of-winner 5181, Fell-in 5191, NEM 5201/5202, Mallet 5173. Pick a fresh one
for lorecannae and record it in CLAUDE.md. Sources: MythosForge `tools/serve.mjs`, CLAUDE.md
"Commands"; BreachForge CLAUDE.md rule 12.

**Test harness** (MythosForge `tests/harness.mjs`, `tools/test.mjs`): a tiny `test(name, f)` /
`runAll(filter)` runner, `eq`/`ok` asserts, helpers that build an exact position, play through
`apply` only, and assert the side effect, not the resolution. Tests are numbered files
(`01-rules.mjs`, `03-player-cards.mjs`...), each test named for the card or the rules term.
**One behaviour test per card in the pool** was the decisive move: MythosForge's per-card tests
found seven engine defects (PLAN.md Status 2026-10-17); MANAFORGE's per-card audit found 13
(Status 2026-10-06); GRAND LINE's found 8 (other-projects.md).

**Sim / arena (AI-vs-AI)**:
- `tools/sim.mjs --games N --seed S --policy random|greedy`: headless games with invariants after
  every step (no card in two zones, no negative resources, no NaN, round never goes backwards,
  `legalActions` non-empty, somebody acts, no pending decision with zero answers). "A crash gate
  and a behaviour readout, never a balance instrument" (MythosForge `tools/sim.mjs` header).
- `tools/arena.mjs` (MANAFORGE): AI in both seats, holdout seed, reports first-player rate of
  decisive games, lands per turn, attack/block rates, **empty-turn rate**, instant-window use,
  mean length (PLAN.md Status 2026-10-03). `--mixed` for cross-deck runs.
- `tools/policy-sweep.mjs` (MANAFORGE) for AI weights; RIVALFORGE BALANCE.md B-8 for the sweep
  method: record the neighbours that measured worse in both directions.
- ChampionsForge D17: the bot is a test instrument (greedy one-step player that follows its own
  follow-up questions); its low win rate is not a difficulty claim.

**Bug-report black box**: `js/bugreport.js` + `tools/replay-report.mjs <trace.json>` reports
ILLEGAL / THREW / DIVERGED; `--selftest` is in the gate (BreachForge PLAN.md "Tools"; MANAFORGE
Status).

**Cache busting for Pages**: `tools/stamp-assets.mjs` rewrites every `<script src>` and
stylesheet to `?v=<sha256 prefix>`; `--check` in CI. Pages sends `max-age=600` per file, so
without it a returning player gets a new `index.html` with a ten-minute-old CSS (BreachForge
CLAUDE.md rule 13).

**Every card project's CLAUDE.md ends with**: "Before committing a document, `ls` every path it
claims exists" (MANAFORGE, MythosForge, GRAND LINE; a document once described a tool that was
never written and survived two days).

### 1.2 Vite/TS 3D family (Mallet, WarMechForge, Dead-of-winner, Fell-in, NEM, Murder Squad)

For reference, and because some of its process conventions are worth borrowing.

- **Stack**: Vite 8 + React 19 + three 0.186 + R3F 9 + drei 10 + zustand 5 + TypeScript 7
  (strict) + Vitest 5 + Playwright + ajv + tsx; GitHub Actions `deploy.yml` (typecheck, test,
  build, deploy on push to `main`); `vite.config.ts` with the Pages sub-path `base`, chunk
  splitting and a second `sounds.html` entry; `playwright.config.ts` honouring `PW_PORT`.
  Source: murder-squad knowledge-base/README "The proven build recipe" 1; Mallet package.json.
- **Docs**: `CLAUDE.md` (read order, owner priorities, token rules, workflow pattern,
  conventions, IP rule, machines), `HANDOFF.md` (current state, next steps, owner questions;
  rewritten, with a "Morning summary (owner)" block at the top after overnight runs), `STATUS.md`
  ("what exists"; agents orient from it only; **rewritten, not appended**), `PLAN.md` (decisions,
  milestones), `KICKOFF.md` (Murder Squad: the owner's answers and the reasoning behind every
  default), `docs/spec/00..60`, `docs/needs-rules-check.md`, `docs/KNOWLEDGE-BASE.md`.
- **Spec-first numbering**: `00-architecture` (frozen contracts), `10-rules-core`, `11-missions`,
  `12-rules-test-checklist` (stable IDs; tests named `it('SHOOT-012 ...')`), `13-golden` (a
  worked turn with forced dice), `20-data-schema` (frozen only after a dry run over every unit in
  the first slice), `30-figures`, `40-ai`, `50-client`, `60-testing`, plus an **edition leak
  list** pasted into every rules prompt (Murder Squad CLAUDE.md; NEM CLAUDE.md "Rules sources").
- **Contracts**: exactly one `PendingDecision` with a `seat`; `legalActions` never empty for an
  open decision; illegal input returns a `Rejection`, never throws; deciders see only
  `view(state, seat)`; the engine owns every number the UI shows (`query.*`). Source: Murder
  Squad CLAUDE.md "Conventions".
- **Gates**: `npm run typecheck`, `npm test`, `npm run validate:data`, `npm run sim -- --games 50`
  (invariants + 2000-decision stall cap), `npm run bench:ai` (normal beats random >= 95%), one
  Playwright full game. Test hooks `?test=1`, `?seats=human,bot&seed=`, `?tier=`, `?speed=`,
  `?gallery`, `?fps`, `?scenario=` (Fell-in/NEM CLAUDE.md "Conventions").
- **The RULING log** (`docs/needs-rules-check.md`), now in every 3D port: one line per ambiguity,
  `RULING: <rule> | <what we did> | <why> | <Status> | <source>`, status words Confirmed,
  Corrected (errata wins), Unsourced, Fan-source. "Rules ambiguities never block work." Volumes:
  Fell-in 120, BT 150, DOW 196, Mallet 282 (Fell-in docs/needs-rules-check.md header; NEM KB §9.7;
  DOW OWNER-REVIEW §3). **Worth adopting for lorecannae** alongside DEVIATIONS.md: DEVIATIONS is
  "what the engine gets wrong"; a RULING log is "how we read an unclear rule".
- **Commit messages**: `M<n>: <what>` + blank line + the current model's Co-Authored-By line
  (3D family); "describe the mechanism, by card code / rule" and end UI commits with what was
  checked on the real page (card family, ChampionsForge hard rules 11-12).

## 2. Owner feedback and complaints (verbatim where the source has it)

### 2.1 On UI and prompts

- "I'm given a choice of keeping or re-rolling a dice, without even knowing what I'm re-rolling
  for" / "dice rolls are being done behind the choice box at the bottom of the screen" / "for
  high AP weapons I should be choosing invulnerable saves, but I have no idea what weapon or AP
  the enemy is using". Fix: every prompt names its subject, the numbers come from state (never
  the last event), numbers on the buttons, the result is never drawn behind the prompt that asks
  about it. Source: Mallet STATUS.md "Client (prompts that say what they are about)".
- "do the same for the shooting and charge prompts. There are some prompts that come up that
  still have no information on what the roll is for." Retrofitting took about 8 commits; build
  self-explaining prompts on day one. Source: Mallet STATUS.md "Client (shooting and charge
  prompts)"; Fell-in KB §7 UI.
- "phases where things happen too fast — a whole bunch of voices mentioning what phase it is, but
  nothing happens in that phase so it skips over it." Fix: 2.4 s phase / 1.6 s turn announcement
  pauses, any click skips. Source: Mallet STATUS.md "Client (narration pauses)".
- "The game doesn't tell me anything about the scenario - objectives, what to do, nothing. It
  feels very unfriendly." Fix: briefing modal, live objective tracker, first-turn hints, shipped
  with the FIRST playable from then on. Source: Fell-in `tools/workflows/m4c-briefings.js`
  OWNER FEEDBACK; NEM KB §9.5. **Lorcana analogue: a how-to-play/briefing, lore-to-win tracker,
  and keyword help in the first playable.**
- "Is the Red Rocket that yellow cube? ... The scenario is set up incorrectly. Go through and make
  fixes." and "explain the basic turn rules somewhere". Source: Fell-in workflows (m4d/m4e
  OWNER FEEDBACK). Content typed from summaries instead of the primary source was wrong.
- Asked late for slim collapsible rails (`[` / `]`), in-game colour options, tooltips for terrain
  and buttons; "make the table the hero". Build them into the first slice. Source: Fell-in KB
  §5.4, §7 UI; DOW brief Part J "UI".
- Native `title=` tooltips are banned in games; one shared Tooltip component, enforced by a test
  (Mallet CLAUDE.md "Conventions"; NEM KB §9.5). Murder Squad's latest: "every game term is
  hoverable (tap on touch)" (commit 2026-10-18 "M7: keyword tooltips").
- DOW OWNER-REVIEW §1 asks for exactly this kind of report: "Blunt and specific is best ('this
  prompt doesn't say what it's for')."

### 2.2 On AI

- RIVALFORGE BALANCE.md B-10: "there were rounds where nothing was played by AI, causing a quick
  loss." Measured: zero-action turns 6-9%, worse at higher difficulty; cause was `pass` scored
  with the whole end-of-round windfall. Lesson: measure behaviour (empty-turn rate), not only
  win rate.
- "The AI opponent is the product" / "A Dead of Winter clone without convincing table-mates is a
  solitaire card game." The AI milestone gets verify loops, a benchmark (>= 95% vs random) and an
  owner playtest gate. Source: DOW CLAUDE.md; Fell-in CLAUDE.md; NEM CLAUDE.md.
- A bot that acts ahead of animations; the bot must wait for presentation idle with a watchdog
  (Mallet HANDOFF resume 2026-09-15; Fell-in KB §5.4).

### 2.3 On audio

- "the shooting sound sounds more like a silenced pistol than a bolt gun… it should also
  correspond to the weapon being used." Measured crest factor 2.2 (real gunshots 8-20); every
  attack played one sound. Fix: flavour map first, measured trims. Source: Mallet STATUS.md
  "Client (weapon-accurate firing sounds)".
- The synthesised score was rejected once ("the music sucks", FABFORGE, per murder-squad
  other-projects.md 7); since then the procedural score is called a placeholder (MythosForge
  PLAN D12, ChampionsForge D7). Always write **"not verified by ear"** until the owner listens on
  `sounds.html` (ChampionsForge docs/sound.md; Murder Squad STATUS.md).

### 2.4 On art and figures

- Terrain: "not in love with the terrain - it's too simple and not shiny, we need more war-torn
  and hurried construction builds, like in war time." Source: NEM HANDOFF.md "Owner feedback
  queue".

### 2.5 On process and cost

- "Please don't make me do the work for you." Free downloads, $0 checkouts, public pages and fan
  databases are the agent's job; stop only for passwords, payment or account creation. Source:
  DOW brief Part A; WarMechForge brief Part A.
- Disappointed by data marked "unverified" and stand-in models after one blocked source:
  "Research before assuming" (DOW brief Part A, citing Whirr Machine).
- Burning tokens: Mallet spent ~4.8M (series view) / ~9M (Fell-in KB §5.1) before anything was
  playable; DOW's first pattern ~8M, the reset ~1.8M. Ceiling about 2.5M tokens per push; 12M for

- Kickoff questions go through the multiple-choice question UI (AskUserQuestion), batched, 4 per

- Owner pushed back on a two-faction first slice ("what about protoss?"): make every faction
  playable in the first run (NEM KB §10 Q7). MANAFORGE D15: owner chose 10 archetypes per era.

- The owner waived the M4 playtest gate and preferred to play "the fully developed game instead"
  (Fell-in HANDOFF 2026-10-17); Murder Squad: "No intervention run. Make the logical choice,

## 3. Overnight and autonomous build practices

### 3.1 What worked

- **The question round** (OVERNIGHT-BUILD-PLAYBOOK §1): ask only where a wrong guess costs rework
  (real names vs original theme, money, art direction, scope); two batches of at most four; list
  every other decision as a stated default the owner can correct in one word.
- **Order of work** (playbook §2; ChampionsForge git log 2026-10-16 shows it literally):
  `.gitignore` alone ("Ignore secrets, scratch, art masters before anything else exists") ->
  authority docs ("regime, rules citation index, rights findings, registers") -> engine spine ->
  first matchup authored -> rest of the pool -> AI -> interface -> art -> sound. Every arrow is a
  commit that runs.
- **First playable milestone named in PLAN** (MythosForge D10 "Roland Banks alone through The
  Gathering"; ChampionsForge D8 "Spider-Man vs Rhino"; MANAFORGE D3 two Bloomburrow starters).
  Then the rest. ChampionsForge did the whole Core Set, 215 tests, 210 art faces in about two
  days (PLAN Status 2026-10-17).
- **Cut order** stated up front, with a "never cut" list (MythosForge/ChampionsForge PLAN "Cut
  order"): deckbuilder -> mode polish -> fanning -> animation beyond spotlight/FLIP; never the
  per-card tests, open-information viewers, the log, the defects gate.
- **Wire every asset pipeline empty with a free `--dry-run`** before the owner supplies a key or
  endpoint (MythosForge T-1/T-2, ChampionsForge HANDOFF "Open items" 1-2). Sample three before
  the batch; idempotent generation (`--force --only <id> --seed-bump 1` to redo one).
- **Contact-sheet review** of every plate in labelled sheets of 16 instead of opening full-size
  renders (MythosForge art-review; ChampionsForge `tools/contact-sheet.py`).
- **Standing approvals written down with dates** (Fell-in KB §5.4: overnight GPU, music budget,
  push without check-in). Restate them inside every art prompt, because art agents refused web
  downloads "without chat approval" although the owner had approved them (NEM KB §10 notes).
- **Morning summary**: "a 'Morning summary (owner)' block at the top of HANDOFF.md: what shipped,
  URLs, screenshot paths, numbered questions" (WarMechForge brief Part A); DOW's `OWNER-REVIEW.md`
  checkbox list (playtest, card data, rulings to skim, decisions for next push, known weaknesses
  fixed without being asked, resolved items) is the best template seen.
- **Two phone notifications**: when playable on Pages, and when the run stops; session stays in
  auto mode with keep-awake (NEM KB §10 Q12-13).
- **Multi-agent, lean**: one stage at a time, Sonnet implementers with exact file lists ("You own
  ONLY: ..."), verify agents never edit, findings routed to the file's owner, schema-validated
  results of 300 tokens or fewer, commit and push after each stage (Fell-in/NEM/DOW CLAUDE.md
  "Workflow script pattern"). The card-game series instead ran a **single agent** by default
  (MANAFORGE D9), splitting bulk card authoring across worktrees by disjoint id ranges with
  disjoint files (BreachForge rule 12; FABFORGE per other-projects.md 7). Murder Squad (newest)
  settled on "one or two agents per milestone".
- **Paste the owner's complaint verbatim** into the stage preamble as "OWNER FEEDBACK driving
  this stage", and declare FROZEN SHAPES inline (NEM KB §9.1; Fell-in workflows).
- **First-time-player review agent**: runs Playwright at 1280x800, reports usability findings,
  never edits (NEM KB §9.1, from Fell-in m4c).
- **Rules-check pass after the content lands**: Mallet re-checked 282 rulings (243 confirmed, 32
  wrong); NEM 83 Confirmed / 50 Unsourced / 9 Corrected (NEM KB §9.1; NEM STATUS "Engine").

### 3.2 What failed

- Big specs and multi-agent engine before anything visible (Mallet; Fell-in KB §5.1, §7 Process).
- Silent `|| {}` fallback drew placeholder art for 59 paid renders and said nothing (playbook §7).
- Two agents in one checkout: `git add` shipped another agent's half-hunk, `--amend` swallowed
  five files, `git reset` orphaned a commit; the main checkout must be an integration tree only,
  land with `git merge --ff-only`, gate the commit not the working tree (BreachForge CLAUDE.md
  rule 12). `preview_start` binds to the PRIMARY checkout's launch config, so a worktree check
  can silently test `main`.
- Sonnet subagents backgrounding long commands and stalling: every prompt says "run long commands
  in the FOREGROUND" with a time cap (Mallet HANDOFF gotchas). Concurrent `npm install` corrupted
  `node_modules`.
- A workflow run that dies leaves finished agents' edits uncommitted: `git status`, run the
  gates, commit by hand, then rerun (Mallet HANDOFF "Workflow scripts"). Resume only works in the
  same session.
- Moving the project folder mid-workflow lost a run; rename by copying and moving the session
  with `change_directory` before `git init` (NEM KB §9.2, §10 notes; StarCraft-TMG HANDOFF).
- STATUS/HANDOFF appended instead of rewritten went stale (Mallet's HANDOFF still said "continue
  to M5" 136 commits later; NEM KB §9.2).
- Overnight Gemini: after about an hour the Windows screen lock hid the tab and uploads stalled;
  keep-awake does not stop the lock. Plan browser-driven generation for when the owner is at the
  PC (NEM KB §10 notes). Claude in Chrome may default to the owner's Mac browser: select the
  Windows one first.
- Scenario/content typed from spec summaries ended in draws until re-entered from the primary PDF
  (NEM KB §9.2). Building a rules-dense subsystem from fan sources, then redoing it from the
  primary book (Fell-in M4b built twice).
- Benchmarking on a matchup you keep rebalancing (NEM KB §9.2). Bench on a fixed pairing.
- Repo hygiene: `.gitignore` had `*.token` not `*.token*` so `elevenlabs.token.rtf` sat untracked;
  a mangled folder named after a Windows Temp path with stripped backslashes; a personal path
  leaked into an early public commit (Murder Squad HANDOFF "Known gaps"). Murder Squad added a
  `.git/hooks/pre-commit` refusing commits that add the owner's name or home path (patterns in
  `privacy-patterns.txt`): **adopt it on day one.**

### 3.3 Machine gotchas (Windows)

Git Bash `/tmp` is invisible to `node` (use `scratch/`); Git Bash eats backslashes in `sed -i` and

that breaks `json.load`; `gh` is not installed per MythosForge/MANAFORGE CLAUDE.md (ChampionsForge's

## 4. IP, rights and NOTICE posture for licensed games

### 4.1 Two postures in use

| | **Card-game reproduction posture** | **"Mallet posture"** (3D ports) |
|---|---|---|
| Used by | MANAFORGE, MythosForge, ChampionsForge, BreachForge, GRAND LINE | Mallet, WarMechForge, DOW, Fell-in, NEM, Murder Squad |
| Card/rules text | **Printed (Oracle/official) text verbatim on the card face**, from one generated pack (`data/printed.js` / `data/cards.js`) that can be switched off and deleted in one commit; the describer is the fallback and auditor | **All prose in our own words**, written from a one-line mechanical summary, never sentence-by-sentence paraphrase; `tools/check-copied-text.ts` guards it (DOW) |
| Names | real names, behind one names constant as the withdrawal lever (`CF.NAMES.mode = 'generic'`; GRAND LINE `js/names.js` characters/original packs) | real unit/card/faction names allowed |
| Art/audio | no official art, frames, set symbols, icons, logos or audio; original generated art; no prompt names an official illustration, artist or studio, never "in the style of" | same; original faction emblems and markings |
| Raw sources | rules text and card dumps only in gitignored `scratch/` | PDFs and community data only in gitignored `docs/sources/` |
| Deployment | researched first; private by default, then the owner usually chose public Pages | public GitHub + Pages from day one |

Sources: MANAFORGE CLAUDE.md regime 3, NOTICE.md; ChampionsForge CLAUDE.md regime 2-3,
docs/takedown.md "Names only"; GRAND LINE NOTICE.md; Fell-in CLAUDE.md "IP rule"; DOW brief Part F.

**For Lorcana, the series precedent for a card game is the reproduction posture** (printed text
on the face, real names behind a names constant). Which posture applies is an owner decision for
the kickoff question round: it touches every data file (playbook §1 lists "real names or an
original theme" as the first question worth asking).

### 4.2 The rights research ritual (do it before engine code)

Every card project records, before the first line of engine code (ChampionsForge/MythosForge
docs/sources.md: "Recorded 2026-10-16, before the first line of engine code (playbook §2)"):
1. A table of **rights holders** and what each owns (publisher of the game; owner of the
   characters; sometimes a third, e.g. GRAND LINE: Bandai, Oda/Shueisha, Toei).
2. For each, the **published fan/community policy**, read from the primary page, with URL, date,
   and HTTP status/byte count; quoted where it bites (GRAND LINE docs/rights.md quotes Bandai's
   2026-07-10 notice).
3. **"Searched on <date>, found none"** is itself a finding and is written down (RIVALFORGE
   docs/sources.md, quoting CARD-GAME-LESSONS-4 §7.2).
4. A plain statement of **where the project sits**, not paraphrased favourably (BreachForge NOTICE:
   "Read plainly, they do not permit this project to be published").
5. The consequence as a PLAN decision (private/local, or public at the owner's request), with the
   concern **stated once** to the owner first.

Findings relevant to Lorcana (Disney characters; game published under licence):
- **Marvel / Disney: "searched 2026-09-23, found none"** — no published fan-art or fan-game
  policy. "Tolerance is not permission, and it is revocable at will." "There is no fair-use
  argument being relied on here and none is claimed." Posture: non-commercial, unofficial,
  clearly labelled, no official assets, names nominative, removed on request. Source:
  MarvelRivalsCCG docs/sources.md "Marvel / Disney"; repeated by ChampionsForge docs/sources.md
  ("Marvel / Disney ... Searched, found none. Tolerance is not permission; no fair-use claim is
  made").
- ChampionsForge's NOTICE names "Marvel Entertainment or The Walt Disney Company" among the
  non-affiliated parties; Lorcana's NOTICE needs the game's publisher and Disney.
- **Not yet researched anywhere in the series: the Lorcana publisher's own fan-content or
  digital-tools policy.** Do it fresh at M0 and record it in `docs/sources.md` (or
  `docs/rights.md`) with date and URL. Riot's Riftbound Digital Tools Policy is the closest
  precedent of a TCG publisher explicitly prohibiting rules-enforcing digital clients
  (BreachForge NOTICE); Wizards' Fan Content Policy likewise does not cover a rules-enforcing
  client (MANAFORGE docs/rights.md "Conclusion"); the Asmodee family's stated position "restricts
  online versions of its games and digitised card games" (ChampionsForge/MythosForge
  docs/sources.md, via Z-Man's IP policy).
- Precedent check is dated and labelled as such: MANAFORGE searched for takedowns of Forge/XMage/
  Cockatrice on 2026-10-03, found none reported in 2026, and wrote "This is not permission; it is
  the current state of the world, dated" (docs/rights.md "Precedent").
- MANAFORGE D16: the owner chose to paint licensed-crossover characters (Final Fantasy, Tolkien)
  "after the concern was stated once". Same pattern applies to Disney characters.

### 4.3 NOTICE.md contents (consensus of MANAFORGE, MythosForge, ChampionsForge, GRAND LINE, RIVALFORGE)

- First line: unofficial, non-commercial fan project; **not affiliated with, endorsed, sponsored
  or approved by** each rights holder by name.
- The game is a product of its publisher; card names, rules text and mechanics belong to their
  owners and are reproduced for personal play only; character names are trademarks used
  nominatively.
- **No official card images, logos, icons, artwork or audio are included**; all illustrations
  original generated art; all sound synthesised or originally generated.
- Nothing is sold; no donations requested.
- Card data imported from <community database> (see `docs/sources.md`); its dataset licence noted
  (MANAFORGE: "MTGJSON (MIT licence for the dataset)... covers the dataset, not the card text").
- Deployment status pointer (to PLAN.md, never stated independently) and takedown pointer: "the
  steps in `docs/takedown.md` are carried out without argument."
- "Built by **evilgouki**."
- The disclaimer also appears **on a screen the player sees** (RIVALFORGE sources.md; Fell-in/NEM
  "README and the UI").
- If the publisher's policy prescribes a disclaimer sentence, copy it verbatim and say where from
  (MANAFORGE NOTICE quotes the Fan Content Policy sentence with its URL and date).
- A contact line: the projects that list one point to opening an issue on the repository
  (ChampionsForge NOTICE). Do not put the owner's personal email or name in it.

### 4.4 docs/takedown.md (MythosForge, ChampionsForge, BreachForge, GRAND LINE)

"These are commands, not intentions." Three levels:
1. Withdraw the hosted copy: disable Pages and make the repo private (`gh api -X DELETE
   repos/<owner>/<repo>/pages`; `gh repo edit ... --visibility private`), or via Settings in the
   browser where `gh` is missing.
2. Make the game unplayable from the repo: `git rm data/cards.js data/decks.js` so load-time
   validation throws on the first frame.
3. Remove all derived material: `git rm -r data art audio`.
Plus "Names only": flip the names constant to the generic pack. BreachForge: deleting the printed
pack leaves a playable game on generated prose.

### 4.5 The stale-notice problem (seen in four projects)

When the owner flips a deployment decision, NOTICE/CLAUDE/takedown drift:
- MythosForge NOTICE.md still says "kept private and undeployed (see PLAN.md D6)" and takedown.md
  says "The project is undeployed", while PLAN D6 was revised 2026-10-18 to a public Pages build.
- MANAFORGE CLAUDE.md still says "Private and local (PLAN.md D1): no remote, no deploy" and
  takedown.md "The repository is private and local", while D12 (same day) made it public.
- BreachForge NOTICE.md says "kept as a private practice tool, run locally and not deployed" while
  PLAN.md records the 2026-09-20 public-deploy decision (and its own "Deliberate scope" still says
  "Not deployed").
- RIVALFORGE CLAUDE.md regime 7 was written because "project 4 shipped three files that disagreed
  about its own deployment status, within three days of writing the rule against it".
**Rule for lorecannae**: deployment status lives in PLAN.md only; NOTICE and CLAUDE.md say "see
PLAN.md"; the commit that changes deployment also rewrites `docs/takedown.md` with the live
commands (RIVALFORGE CLAUDE.md regime 7). The playbook's "before handing back" checklist: "Grep the
repo for every file restating a decision that moved."

### 4.6 Secrets and privacy

- `.gitignore` in the first commit, before any tool exists: `tokens.txt`, `tokens.txt.txt`,
  `Tokens.txt`, `hf_token.md`, `elevenlabs.token.rtf`, `*.token*`, `.env*`, `scratch/`,
  `art/masters/`, `art/archive/`, traces, `node_modules/`, `.claude/` (MythosForge `.gitignore`).

  root at runtime (`path.resolve` from the script location); grep staged changes before every

## 5. Newer than 2026-10-03: what contradicts or extends the card-game KB

### 5.1 Card-engine lessons from the two co-op card games (Oct 16-18)

- **Ops held as lambdas are lost in a JSON clone of the state**: register ops in ability data by
  id at load, and have queue items carry the id (ChampionsForge PLAN D14, found by random play on
  one card). Conditions are small predicate lambdas; effects are op data (D13).
- **Pure resolution queue**, not ask-by-replay, when interrupt windows nest with their own costs;
  payment incremental, one source per action, full rewind on cancel (ChampionsForge D11).
  MythosForge kept MANAFORGE's "effect runs on a clone, a question discards the partial run and
  the answer re-runs it" shape (MythosForge D8). Both are proven; pick by how deeply windows nest.
  Lorcana's bag/triggers and "challenge" windows are shallow compared with Magic's stack.
- **Click acts (one option) or opens a menu (several); inspect by 300 ms hover, right-click or
  long-press.** This departs from CARD-PRESENTATION-SPEC's "tap inspects, drag commits" because the
  cards carry several actions each (ChampionsForge D15). MANAFORGE TODO also still lists drag to
  play as not done. Decide per game; Lorcana characters can quest, challenge, sing or use
  abilities, so the menu pattern likely fits.
- **Undo only while nothing hidden was revealed** by the undone answer; undo must never be a peek.
  **Mutes** are a UI-level standing instruction to pass for named cards this round, so the
  engine's never-assume rule stays intact (ChampionsForge D18).
- **Auto-pass windows when the player holds nothing playable**, with a toggle that forces every
  window (MythosForge D5; MANAFORGE D4 "stops" with per-step toggles and "pass to end of turn",
  justified by the rules' own shortcut clause).
- **Prompts show the odds** computed by the engine when randomness is open information
  (MythosForge D13 `AH.testOdds`); same principle as Mallet's prompt fixes.
- **Hand fanning by spec Model B** (flat row while it fits, then an overlap fan at ±3° with hover
  lift; shrink under 1200 px); the arc fan (Model A) was rejected because the printed text is read
  in place (MythosForge TODO T-5). Lorcana cards are read in hand too.
- **Hotseat display** for multi-handed solo (ChampionsForge D12); not needed for 1v1 vs AI, where
  the opponent's hand is a count.
- **Campaign/progression state engine-side from day one**: "Retrofitting campaign state later is
  the same misery as retrofitting a names file" (MythosForge D4).
- **"A rule with two homes is worse than a rule with none"** (BreachForge PLAN, 2026-09-20; may
  already be in LESSONS-4).
- **Starter decks reconstructed by a stated rule are labelled `inferred`** on the deck screen and
  listed under "Not deviations" (MythosForge D9, ChampionsForge D10, citing LESSONS-6 §6).
- **Card data from a community database's public API** dumped to `scratch/cdb/` (ArkhamDB
  `/api/public/cards/core.json`, MarvelCDB, MTGJSON), errata taken from the database; rules from
  the official reference cited by **term** when it is a glossary (page numbers move between
  versions) or by section number when numbered (MythosForge D14, ChampionsForge docs/sources.md
  "Rules").
- **A `rules-index --check` gate** proves every cited rule term exists in the reference text
  (MythosForge gate; "53 terms, all found").
- **The bot is not an opponent in co-op**; the 1v1 zero-sum evaluator `sideValue(me) -
  sideValue(them)` does not apply (ChampionsForge regime 5). Lorcana is 1v1 by default, so the
  zero-sum evaluator applies again (BreachForge/RIVALFORGE regime: "1v1 only").

### 5.2 Process changes that supersede older guidance

- **Projects moved out of OneDrive** to `C:\Claude Code Projects\` ("outside any synced folder",
  ChampionsForge D1, MythosForge D1, NEM KB header). The OneDrive worktree-path rule in
  BreachForge/RIVALFORGE CLAUDE.md rule 12 matters less now, but its other half stands: one agent
  per worktree, the main checkout is integration-only, `preview_start` serves the primary
  checkout.
- **Lessons copied into `docs/lessons/`** of each new card repo (MythosForge, ChampionsForge),
  scrubbed of the owner's name, instead of the repo root as MANAFORGE/GRAND LINE/RIVALFORGE did.
  MythosForge's `docs/lessons/HANDOFF-MAGIC.md` is MANAFORGE's HANDOFF.md renamed, and is "read
  first".
- **The Workflow-tool pattern** (one stage, at most 8 then 15 agents, Sonnet implementers) is the
  3D family's norm; Murder Squad, the newest, scaled back to "one or two agents per milestone"
  with agent briefs and exact file lists.
- **Kickoff record as its own file** (`KICKOFF.md`, Murder Squad): the questions, the insights from
  the KB that shaped defaults, the owner's answers, every decision with its reason, a milestone

### 5.3 Art and audio pipelines changed

- **Art is now local and free**: the owner's Flux Studio (job API on port 7880, ComfyUI on 8188,
  FLUX.2 klein 4B, Apache-2.0, about 6-15 s per plate on the RTX 5080): `POST /api/jobs {model,
  prompt, aspect, megapixels, batch, seed}`, poll `/api/jobs/<id>` until `done`, fetch
  `/files/<id>/<image>`; `POST /api/settings {freeAfter:false}` keeps the model loaded. Klein was
  chosen over FLUX.1 dev after a three-card sample. This supersedes the paid Hugging Face
  FLUX.1-schnell route of the earlier card games and MANAFORGE's local SDXL (D13). Sources:
  MythosForge TODO T-1, PLAN D11; ChampionsForge D16; murder-squad local-ai-studios.md.
- **Audio is now local too**: since 2026-10-17 the local Audio Studio (port 7890: ACE-Step music,
  Stable Audio Open SFX, Qwen3-TTS/Chatterbox voice) replaces ElevenLabs, at zero credit cost
  (Murder Squad PLAN "Audio"; murder-squad KB README rule 9). MythosForge and ChampionsForge
  (Oct 16) still say "procedural now, ElevenLabs later"; they predate the switch. Keep the
  manifest-override shape: a file whose name matches a synth voice replaces it; the synth stays
  as the floor (ChampionsForge docs/sound.md). One lazy `AudioContext` created by the first
  gesture; a lookahead scheduler on `currentTime`, never `setTimeout`; voices keyed off the
  structured log (ChampionsForge docs/sound.md "How it works").
- **GPU etiquette**: one job at a time per machine, announce GPU work (another session may hold
  the queue for minutes), never kill node by image name (Fell-in KB §3.5; local-ai-studios.md).
- **Flux prompt lessons** (MythosForge docs/art-review-2026-10-17.md; ChampionsForge
  docs/ART-PROMPT-RULES.md), on top of the KB's art-prompt rules:
  - A proper noun in a clause invites lettering ("the town of Arkham" became a title banner on
    seven cards); "magazine cover" drew a gibberish banner, so ask for an interior illustration,
    full-bleed and wordless. ChampionsForge bans "comic book", "comic", "panel", "page", "cover",
    "splash" and a long list of text-magnet nouns (sign, banner, logo, emblem, book, map, screen...);
    chest emblems are described as shapes.
  - A vague noun ("shape", "creature", "figure") is filled by the model's prior: "a hulking shape"
    drew a naked man, "a dozing hunched creature" a bear; name the thing. "Cadaverous" or "hollow"
    makes a skull.
  - Objects drew by trait, not by card (a tote bag as a lamp, a magnifying glass as a spoon);
    template prompts gave nine skills one portrait. Fix: a per-card SCENE table (92 hand-written
    clauses in original words), each card its own subject and setting.
  - No negations (diffusion reads the noun); no counts above two; one identity clause per
    character so a character on several cards reads identically; no named locations that carry
    signage. Flux image edit ignores negations too: say what is wanted.
  - QC each plate on contact sheets against its prompt and its card; regenerate on lettering,
    resemblance to an official illustration, mush at thumbnail size, a surviving signature, or
    broken hands. "Recognisable at 120 px, never a copy at 600 px."
  - The lint refuses to run on a violation, before any GPU time is spent.
- **Art direction per project, chosen by the owner, recorded as "DO NOT RE-LITIGATE"** with one
  STYLE constant; changing one character starts a new set (ChampionsForge ART-PROMPT-RULES).
  Examples since Oct 3: 1920s pulp-magazine ink and gouache (MythosForge D11), bold graphic-novel
  ink (ChampionsForge D6), 15-style mix (MANAFORGE D17). Run a style audition (several directions
  on one card) before choosing (MANAFORGE D14).
- **Concept approval is delegated to Claude** for figures; send contact sheets as FYI
  (murder-squad KB README rule 7, Mallet 2026-10-16).

### 5.4 Hidden information (DOW, relevant to Lorcana's hand, deck and face-down inkwell)

  "Conventions"; Fell-in KB §7 Engine: two leak bugs were fixed in DOW).
- The end-of-game recap reveals every hidden decision so the human can audit that the bots played
  fair (DOW README "Fairness rules").
- `?seed=<word>` in the URL makes bug reports repeatable (DOW brief Part A).

### 5.5 AI targets and harnesses since Oct 3

- Bench gate: normal tier beats random in at least 95% of games (Fell-in 95-98%, NEM 239/240,
  Murder Squad 40-0); easy at about 75-80%; run the AI in a Web Worker with a time budget behind
  an env var and a 3 s timeout with random fallback (NEM STATUS "AI"; NEM KB §9.3).
- Bench on a fixed pairing plus the main matchup; an equal-skill match sits near 50% when one
  side is simply stronger, so report point/lore difference too (Murder Squad HANDOFF "Known gaps").
- Every code hook needs a test proving it fires in a real game; zero-cost reactions loop forever
  (one per window plus a stall cap); a fuzz test asserts every listed option is accepted (NEM sim:
  "every listed option is accepted (1 in 20 decisions, on a clone)").
- MANAFORGE (Oct 7): the AI holds instant mana open and acts on the opponent's turn only at
  meaningful windows; measured as "casts in 3.8% of the opponent's-turn windows where it could".
  Measure the AI's reactive behaviour, not only its own turns.

## 6. Ready-to-use checklist for lorecannae's M0 (synthesised from the above)

1. `.gitignore` committed alone (secrets, `scratch/`, art masters), plus the privacy pre-commit
   hook (Murder Squad).
2. Rights research in `docs/sources.md` / `docs/rights.md`: the game's publisher policy (new
   research), Disney (series finding: none published), the card database's licence; consequence as
   a PLAN decision; concern stated once.
3. Kickoff questions via the multiple-choice UI, at most 4 per batch: printed text vs own-words
   posture and real names; deck pool size for the first night; art direction (offer an audition);
   public Pages or private; token ceiling. Everything else as stated defaults in a `KICKOFF.md`.
4. CLAUDE.md with the regime and hard rules (copy MANAFORGE/MythosForge's), a fresh port in
   `.claude/launch.json`, `docs/rules.md` citation index into the official comprehensive rules.
5. PLAN.md (decisions table, cut order, dated Status), DEVIATIONS.md, TODO.md, `data/defects.js`
   wired into the deck picker on day one, NOTICE.md, `docs/takedown.md`, and a RULING log.
6. Engine spine + `tools/{serve,test,check-pages,sim,build-cards,audit-cards,replay-report,gate}.mjs`;
   one behaviour test per card; the leak test for hidden zones in the sim.
7. First playable: two starter decks vs a greedy bot in the real browser, with self-explaining
   prompts, keyword hover help, a lore tracker and a how-to-play panel from the first build.
8. Then the full pool, the arena (both seats, decisive results, empty-turn rate), art on the local
   Flux Studio (dry run, three samples, contact sheets), audio on the local Audio Studio, and the
   animation layer. Say "not verified by ear" until the owner listens.
